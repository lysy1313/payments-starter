# Frontend — модуль 2: Stripe Checkout

React + TypeScript + Vite. Разовая покупка через Stripe подключена к серверному API и работает в Sandbox. PayPal, подписка, история платежей и автопродление пока используют демонстрационные экраны.

## Запуск

Из корня проекта в двух терминалах:

```sh
npm run dev:backend
```

```sh
npm run dev:frontend
```

Откройте http://localhost:5173. Сервер должен работать на порту 3001. В его `.env` уже должны быть настроены подключение к БД, тестовый серверный ключ Stripe и `FRONTEND_URL=http://localhost:5173`.

В локальном backend необходимы эндпоинты из модулей 1 и 2, включая `POST /api/payment-attempts/:id/checkout`. Здесь изменяется только frontend, уже написанный backend заменять не нужно.

## Как запускается оплата

1. Страница загружает активный товар `one-time` через `GET /api/products` и показывает серверную цену.
2. Нажатие «Перейти к оплате» создаёт заказ через `POST /api/orders`. В теле только `productId` и `quantity`; цену и валюту определяет сервер.
3. Создаётся попытка оплаты: `POST /api/orders/:id/payment-attempts`.
4. Запускается Checkout: `POST /api/payment-attempts/:id/checkout`.
5. Браузер переходит на `checkoutUrl`, полученный от сервера.

Во время подготовки оплаты кнопка, количество и выбор варианта блокируются. Ошибка показывается на странице. При повторе после ошибки используются уже полученные ID заказа и попытки для того же количества. Это действует только пока открыт этот компонент. Потерю ответа, перезагрузку, параллельные вкладки и полную серверную идемпотентность разберём в последующих модулях.

Для PayPal и подписки кнопка называется «Открыть предпросмотр» и открывает демоокно без создания заказа или платежа.

## Возврат из Stripe

Checkout возвращает на корневую страницу с параметрами `checkout=success` или `checkout=cancelled` и `orderId`. При успехе также передаётся `session_id`.

Приложение запрашивает `GET /api/orders/:id` и отображает результат по серверному статусу. Параметр `checkout=success` сам по себе не подтверждает оплату. Заказ со статусом `pending` показывается как ожидающий подтверждения. При отмене перехода в Checkout статус заказа не меняется.

На этом этапе после тестовой оплаты ожидается `pending`: подтверждение оплаты через webhook будет добавлено в модуле 3. Кнопка «Проверить статус» повторяет только чтение заказа. «Закрыть» убирает уведомление и параметры возврата из URL.

История платежей ещё не связана с API и не пополняется после Checkout.

## Файлы

| Файл | Назначение |
|---|---|
| `src/api/payments.ts` | Типы ответов и запросы к API |
| `src/pages/PurchasePage.tsx` | Загрузка цены, количество и запуск оплаты |
| `src/components/CheckoutReturn.tsx` | Чтение статуса заказа после возврата |
| `src/App.tsx` | Показ и закрытие уведомления о возврате |
| `src/styles-checkout.css` | Стили уведомлений и ошибок |
| `vite.config.ts` | Локальный proxy `/api` на backend |

Proxy сохраняет префикс `/api` и направляет запросы на `http://127.0.0.1:3001`. Эта настройка относится к серверу разработки Vite; маршрутизацию API для публикации настроим отдельно.

## Проверка

```sh
npm run typecheck --workspace frontend
npm run build:frontend
```

В браузере проверьте запуск Stripe для количества 1 и 2, успешную тестовую оплату, возврат без оплаты и отображение ошибки при недоступном backend.
