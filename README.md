# Payment Lab — старт для обучения платежам

В архиве два проекта: `frontend` с готовым интерфейсом и `backend` с пустым каркасом сервера. Они работают независимо. Бизнес-логику, базу данных и подключение платёжных систем будем писать в ходе обучения.

## Запуск

Нужен Node.js **24 LTS**: https://nodejs.org/. Распакуйте архив и откройте терминал в папке `payments-starter`, где лежит этот README и корневой `package.json`.

Один раз установите зависимости обоих проектов:

```sh
npm ci
```

Запустите frontend:

```sh
npm run dev:frontend
```

Откройте http://localhost:5173. Готовый интерфейс работает без backend. Дождитесь сообщения Vite о запуске перед открытием страницы.

Во втором терминале в той же корневой папке можно отдельно запустить backend:

```sh
npm run dev:backend
```

Проверка сервера: http://localhost:3001/api/health

Остановка любого процесса — Ctrl+C. Команды подходят для терминала Windows, macOS и Linux.

## Что готово

| Frontend | Backend |
|---|---|
| React + TypeScript + Vite | Node.js + TypeScript + Express |
| Покупка и выбор способа оплаты | Точка входа и настройки порта |
| Экран успеха, ошибки и ожидания | Маршрут `GET /api/health` |
| История платежей с фильтрами | Обработка неизвестных маршрутов и ошибок |
| Демо управления подпиской | Пустые папки controllers/services/db |
| Адаптивные стили и модальные окна | Экспорт приложения отдельно от локального запуска |

Здесь нет готовых эндпоинтов заказов, схемы БД, платёжных SDK, webhook, реальных ключей или API-вызовов с frontend. Цены и записи истории — статичные примеры. Никаких операций с деньгами проект выполнить не может.

Этот комплект нужен, чтобы заниматься платежной логикой без работы над вёрсткой. После подготовки проекта начнём маленькими заданиями: сначала модель заказа, затем свой API, затем тестовая платёжная интеграция.

## Структура и работа

Это npm workspace: два отдельных `package.json`, одна установка и общий `package-lock.json` в корне. Отдельные объяснения файлов находятся в `frontend/README.md` и `backend/README.md`.

В репозиторий можно добавить весь `payments-starter`. Не добавляйте `node_modules`, `dist` и `.env`; они исключены через `.gitignore`. В архиве нет чужих проектов и ранее написанных решений урока.

Все проверки и сборки:

```sh
npm run check
```

Для одного проекта доступны `npm run build:frontend` и `npm run build:backend`.

Публикацию на Vercel выполним отдельным шагом. Frontend на Vite и точка входа Express подготовлены для этой платформы; публичный деплой пока не выполнялся. Для будущего подключения внешней PostgreSQL-базы локальное дисковое хранилище не используется.

Официальные материалы: https://vite.dev/guide/ и https://vercel.com/docs/frameworks/backend/express
